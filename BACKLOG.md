# Tool backlog

Durable record of known tool defects and deferred fixes, each with its
revive condition. Items here were previously scattered across
retrospectives and gitignored plan docs; this file is the authoritative
list. Fixing an item mid-program follows the usual rule: tool changes
that could alter a registered rule's output are made between trials,
never silently mid-sweep.

## Closed

| # | Item | How it was closed |
|---|---|---|
| D-9 (skill half) | The agent skill was not shipped in the package, so a user who installed with pip had no copy, and a user with a clone had to copy the directory into their project by hand. | Closed 2026-11-23. The skill ships as package data (`proofhouse/data/skill/SKILL.md`, a byte-for-byte copy of `.claude/skills/proofhouse/SKILL.md`; a test fails if the two differ) and `proofhouse install-skill` copies it into `./.claude/skills/proofhouse/`, into `~/.claude/skills/` with `--user`, or under any skills directory with `--dest`. An identical file is left alone and a different one is refused unless `--force` is given. A separate command, not a side effect of `init`, so nothing is written into a project that did not ask for it. The remainder of D-9 stays open above. |
| D-10 | `amend` accepted a successor whose `validation_blocks` re-declared a block its parent had already spent (the registry refused this only for an invalidating amendment), and `verify` then held a permanent error no later successor could clear. Found by the 2026-10-11 stranger-agent test. | Closed 2026-10-12. The registry refuses any declared single-use block that anyone has spent, at every registration, naming the block, the spender, whether the spender is in the lineage, and the fix (`validation_blocks: []`, or blocks that postdate the change). Mirrors `verify`'s `_check_runnable` error so the two cannot disagree. Unspent blocks declared by a parent remain reusable by its successor. |
| D-12 | A second `run_eval` by the same entry on a V block it had already spent was recorded, and a plain `gate` on it rendered a second decision-grade verdict; and the score function was a callable the eval script handed in, covered by no pin. Same test. | Closed 2026-10-12. `run_eval` refuses an eval on a single-use block this entry already recorded an eval on, before consumption; keyed on the ledger row, not on consumption, so reserve-then-validate by one entry (B-7) and repair-and-rerun after a broken pipeline both survive; subperiod runs are exempt. `score_fn` is read from the pinned artifact when not supplied; a supplied callable whose source is the pinned file counts as pinned; the manifest records the source inside the chained digest; `verify` reports a caller-supplied function as a warning and a pre-pin manifest as unverifiable; `report` prints the line. |
| D-6 | The screening engine had no command. `run_screen`, both step-up procedures and `ledger.append_screen` all existed and were tested, but nothing outside the tests called them, so screening a batch meant writing a script by hand — the same "correct code, no caller" shape S-2 exists to catch, one level above where S-2 looks. | Closed 2026-09-14. `proofhouse screen` added. It screens the stage-1 runs the ledger already holds, the way `gate` reads the run it renders a verdict against, and records the batch, m, q, method and threshold as a `screen` row. The batch rules now live in one place (`check_screen_batch`), shared by the command and by `run_screen`. |
